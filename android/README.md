# Android app

World Up on the Play Store: a native Android shell, built with [Capacitor](https://capacitorjs.com), whose own WebView shows https://worldup.alng.fr full screen, with no browser in between (spec, "Application Android"). The interface stays the site's: a site deployment updates the app, and the app needs a new release only for its name, icon, colors, Android version or native plugins.

What the app does natively, where a WebView can't do what a browser does:

- **Google sign-in**: Google refuses its sign-in page in a WebView. The site asks the phone's own Google sign-in (Credential Manager, through `@capgo/capacitor-social-login`) for an ID token, which Better Auth checks and signs in with (`src/components/account/GoogleButton.tsx`). At the first launch, the home page offers the phone's Google accounts at once, in the sheet that rises from the bottom (`GoogleAppPrompt`); a Google account with no World Up account goes on to the signup form, which only asks for the pseudo and birth date.
- **Notifications**: a WebView has no Web Push. The phone registers with Firebase Cloud Messaging, the server keeps its token as a device next to the browsers', and the worker sends through Firebase (`src/lib/notifications/app-push-device.ts`, `src/worker/fcm.ts`). They show while the app is open too (`presentationOptions` in `capacitor.config.ts`), and touching one opens its page.
- **The site's links** (address confirmation and password reset e-mails, shared card pages) open in the app, verified by the site's `/.well-known/assetlinks.json` (`AndroidManifest.xml`, `MainActivity.java`).
- **Offline**: a page packaged with the app (`native/www/index.html`) says so and tries again. The site's own error pages (404, 500) still show.
- **Back button**: Capacitor's App plugin isn't used. The back button goes to the previous page, or puts the app in the background from the first one (`MainActivity.java`).
- **Session**: the WebView writes its cookies to disk every 30 s or so; `MainActivity` writes them as soon as the app goes to the background, so that a player who closes the app right after signing in stays signed in.
- **Splash screen**: the logo on the site's ground, light or dark like the phone, until the first page is drawn (`NativeApp.tsx`) or for 3 s. From Android 12 the system draws it from `splash_icon.xml` (`values-v31/styles.xml`): the launcher icon can't serve, since its logo is in its background layer, which the splash leaves out. The WebView is transparent until the site paints its ground, over the same logo (`activity_main.xml`), so that a site slow to come shows the splash a little longer rather than an empty screen.
- **Downloads**: a WebView doesn't download by itself. A file the site sends as an attachment (the player's data, `/account/export`) goes through Android's download manager, with the session's cookies, into Downloads (`MainActivity.java`).
- **Other sites** (Wikipedia, Commons, the licences) open in a tab over the app (Custom Tabs, `androidx.browser`), in the site's colors, which closes back to the game; Capacitor would send them to the browser.
- **System bars**: the strips behind the status and navigation bars take the ground of the page at the top of the screen, with icons that stand out on it: the theme forced in the game, the pack opening's dark stage. The site tells the app with the app's own `SiteGround` plugin (`SiteGroundPlugin.java`, `src/lib/app-system-bars.ts`); an older app ignores it and keeps the phone's theme.
- **No scrollbar**: the WebView shows none while it scrolls, like a native screen.
- **Vibrations**: the pack opening's and the streak screen's go through `@capacitor/haptics` (`src/lib/effects.ts`); an app built before it has none.
- **Shortcut**: a long press on the launcher icon offers "Ouvrir un paquet" (`res/xml/shortcuts.xml`, its icon `ic_shortcut_open`), which opens the default collection's opening page; `app/build.gradle` builds that address from the server URL (`shortcut_open_url`).

The site finds out it runs in the app with `isNativeApp()` (`src/lib/native-app.ts`). In a browser nothing changes.

## Layout

- `capacitor.config.ts` (repository root): the app ID, the site's address, the plugins' settings.
- `android/`: the Android project, generated by `npx cap add android` (Capacitor 8), then edited: `MainActivity.java` and `SiteGroundPlugin.java`, `AndroidManifest.xml`, the icons, splash and layout in `res/`, the version, signing and Custom Tabs in `app/build.gradle` (its version in `variables.gradle`).
- `native/www/`: what Capacitor packages, the offline page only.
- The plugins' native code comes from `node_modules`: `npx cap sync android` writes their list into the project (`capacitor.settings.gradle`, `app/capacitor.build.gradle`), and copies `capacitor.config.ts` and `native/www` into it (git-ignored). Run it after changing either, or after updating a Capacitor package.

## Build

Actions > Android app > Run workflow, with the version shown on the Play Store (`1.0.0`) and the site the app shows (production by default; staging to try a server change before deploying it). The run's artifact, `world-up-<version>-<run number>`, holds:

- `app-release.apk`, to install on a phone;
- `app-release.aab`, to upload to the Play Console.

Both are signed with the upload key. The `versionCode` is the run number, so each build gets a higher one, as the Play Store requires. A pull request that touches the app (`android/`, `native/`, `capacitor.config.ts`, `package-lock.json`) builds it unsigned, to check it still compiles. A staging build has the same application ID: it replaces the production app on the phone.

## One-time setup

1. **Upload key**: create it on your computer, and keep it with its password outside the repository (a lost upload key can be reset by Google support, after some days):

   ```sh
   keytool -genkeypair -storetype PKCS12 -keystore upload-key.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=World Up"
   ```

   The alias must be `upload` (`app/build.gradle`). The keystore holds one password, for the store and the key. Add two repository secrets (Settings > Secrets and variables > Actions):
   - `ANDROID_KEYSTORE_BASE64`: the key file in base64, `base64 -w0 upload-key.jks` (PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-key.jks"))`);
   - `ANDROID_KEYSTORE_PASSWORD`.

2. **Play Console**: create the app, keep Play App Signing (Google holds the key that signs what the Play Store installs), and upload the first `.aab` by hand. The store listing takes `public/icons/maskable-512.png` as its icon: a full square, which Google rounds itself.

3. **The site's links**: in the server's `.env`, set `ANDROID_APP_ID=fr.alng.worldup` and, in `ANDROID_CERT_FINGERPRINTS`, the SHA-256 fingerprints separated by commas:
   - the app signing key: Play Console > Test and release > App integrity > Play app signing;
   - the upload key, which signs the APK: the summary of any workflow run shows it.

   Then `docker compose up -d`, and check https://worldup.alng.fr/.well-known/assetlinks.json. Until it lists the app, the site's links open in the browser.

4. **Google sign-in**: in the Google Cloud project that holds the site's OAuth client (`GOOGLE_CLIENT_ID`), APIs & Services > Credentials > Create credentials > OAuth client ID, type "Android", package name `fr.alng.worldup`, with the **SHA-1** fingerprint of the app signing key (Play Console, as above). Add a second Android client with the upload key's SHA-1 (the workflow run's summary) for the APKs installed by hand. These clients are only declared: the app asks for a token issued to the site's web client, which the server already accepts, so nothing to copy anywhere.

5. **Notifications**: create a Firebase project on the same Google Cloud project (console.firebase.google.com > Add project > pick it), then:
   - Project settings > General > Add app > Android, package `fr.alng.worldup`; download `google-services.json` and add it as the repository secret `GOOGLE_SERVICES_JSON_BASE64` (`base64 -w0 google-services.json`). It is not committed.
   - Project settings > Service accounts > Generate new private key: in the server's `.env`, `FCM_SERVICE_ACCOUNT` is that JSON file in base64 on one line (`base64 -w0 key.json`). It is a secret: keep the file nowhere else.
   - `docker compose up -d`: the worker now sends to the app, and `/activity` shows the switch in it. Both the web and the worker read the key: the web, when an event happens, queues a push only for the kinds of device that are on.

   Set both, or neither: a build without `google-services.json` can't register for notifications, and turning them on in it fails.

## Changing the app

- Name: `appName` in `capacitor.config.ts` and `app_name` in `app/src/main/res/values/strings.xml`. Colors: `res/values/colors.xml` (and `values-night/`), `capacitor.config.ts`. A new launcher icon or splash needs a new release.
- The launcher shortcuts: `res/xml/shortcuts.xml`, their labels in `strings.xml`, their address in `app/build.gradle`. A shortcut needs a new release.
- The site's paths that open in the app: the intent filter in `AndroidManifest.xml`. Never `/api/auth/callback/`: a Google sign-in started in the phone's browser must come back to the browser.
- The position, for the map's "Je suis ici" and "Autour de moi": `ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION` in `AndroidManifest.xml` (added on 2026-11-23); Capacitor's WebChromeClient asks the player when the site first asks the WebView. An app built before them refuses the position: they need a new release, with the Play Console's data safety form declaring the precise location (sent to the server for "Je suis ici", checked and not kept).
- Every year Google Play requires a recent target Android version (August 31 for new releases): raise `targetSdkVersion` and `compileSdkVersion` in `variables.gradle`, usually with a Capacitor update.
- Capacitor packages (`@capacitor/*`, `@capgo/capacitor-social-login`) move together: Dependabot groups them. After an update, `npx cap sync android`, and commit what it changed in `android/`.

## Local build

With JDK 21 and the Android SDK (`ANDROID_HOME`), from the repository root. Android Studio installs the SDK (`%LOCALAPPDATA%\Android\Sdk`) and an emulator, but the JDK it bundles (`jbr`) is too recent for Gradle 8.14: point `JAVA_HOME` at a JDK 21, such as one in `~/.jdks`.

```sh
npm ci
npx cap sync android        # CAPACITOR_SERVER_URL=https://<staging> for staging
cd android
./gradlew assembleRelease   # unsigned; ANDROID_KEYSTORE_PATH and ANDROID_KEYSTORE_PASSWORD sign it
```

To try a branch on the emulator against the local site, before any deployment:

```sh
npm run build && npx next start                              # the site, on port 3000
CAPACITOR_SERVER_URL=http://localhost:3000 npx cap sync android
cd android && ./gradlew assembleDebug
adb reverse tcp:3000 tcp:3000                                # the phone's localhost:3000 is the computer's
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Plain HTTP is allowed for such a build only (`cleartext` in `capacitor.config.ts`). Run `npx cap sync android` again afterwards, so that the project points at production. A debug build's pages can be inspected from Chrome on the computer (`chrome://inspect`), or driven through `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`. A link clicked by a script doesn't count as the player's gesture: Chromium then skips its history entry, and the back button with it. Tap the screen instead (`adb shell input tap`).
