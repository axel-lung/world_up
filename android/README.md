# Android app

World Up on the Play Store: a Trusted Web Activity that opens https://worldup.alng.fr full screen in the phone's browser (Chrome, or another that supports it), without an address bar (spec, "Application Android"). Everything stays on the server. A site deployment updates the app; the app needs a new release only to change its name, icon, colors or Android version.

## Build

Actions > Android app > Run workflow, with the version shown on the Play Store (`1.0.0`). The run's artifact, `world-up-<version>-<run number>`, holds:

- `app-release.apk`, to install on a phone;
- `app-release.aab`, to upload to the Play Console.

Both are signed with the upload key. The `versionCode` is the run number, so each build gets a higher one, as the Play Store requires. A pull request that touches `android/` builds the app unsigned, to check it still compiles.

## One-time setup

1. Create the upload key, on your computer, and keep it with its password outside the repository (a lost upload key can be reset by Google support, after some days):

   ```sh
   keytool -genkeypair -storetype PKCS12 -keystore upload-key.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=World Up"
   ```

   The alias must be `upload` (`app/build.gradle`). The keystore holds one password, for the store and the key.

2. Add two repository secrets (Settings > Secrets and variables > Actions):
   - `ANDROID_KEYSTORE_BASE64`: the key file in base64, `base64 -w0 upload-key.jks` (PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-key.jks"))`);
   - `ANDROID_KEYSTORE_PASSWORD`.

3. In the Play Console, create the app, keep Play App Signing (Google holds the key that signs what the Play Store installs), and upload the first `.aab` by hand. The store listing takes `public/icons/maskable-512.png` as its icon: a full square, which Google rounds itself.

4. In the server's `.env`, set `ANDROID_APP_ID=fr.alng.worldup` and, in `ANDROID_CERT_FINGERPRINTS`, the SHA-256 fingerprints separated by commas:
   - the app signing key: Play Console > Test and release > App integrity > Play app signing;
   - the upload key, which signs the APK: the summary of any workflow run shows it.

   Then `docker compose up -d`, and check https://worldup.alng.fr/.well-known/assetlinks.json. Until it lists the app, the app shows an address bar.

## Changing the app

- Name, colors, address: `twaManifest` at the top of `app/build.gradle`. `twa-manifest.json` records the same values for Bubblewrap.
- Every year Google Play requires a recent target Android version (August 31 for new releases): raise `compileSdkVersion` and `targetSdkVersion` in `app/build.gradle`.
- The project was generated by Bubblewrap 1.27.0 (`@bubblewrap/core`), then edited: the version and the signing come from the workflow, `minSdkVersion` is 24 (android-browser-helper 2.7 requires it), and the repositories are Maven Central instead of JCenter. `npx @bubblewrap/cli update` regenerates the project from `twa-manifest.json`, icons included (it downloads them from the site), but overwrites those edits: put them back from `git diff`. The splash screens (`drawable-*/splash.png`) are the cut-out logo (`design/logo/world-up-cutout.png`) rather than the icon, so that no cream square shows on the splash's ground: put them back too.

Notification delegation is on (`DelegationService`, the `POST_NOTIFICATIONS` permission). Once the site sends Web Push notifications, they show as the app's own, with no new release; the app asks for the permission only when the site does.

## Local build

With JDK 17 and the Android SDK (`ANDROID_HOME`):

```sh
cd android
./gradlew assembleRelease   # unsigned; ANDROID_KEYSTORE_PATH and ANDROID_KEYSTORE_PASSWORD sign it
```
